# 闸对

中文名：**闸对** · 前缀 `gatetwin` · 端口 **6500 / 11500**

## 骨架

**刷卡点装载 → 同卡进站出站成对物化 → 缺腿/异向/超时旁路 → 行程账与刷卡点互证**

皮：地铁/公交闸机刷卡。去皮是 **OD 成对管道 + 开腿态 + 旁路 + 行程贯验**，不是票务售票 CRUD、不是乘车码业务页、不是日结封账。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6500
# 刷卡流 → 灌「成对样例」→ 看开腿账/行程账 → 再灌「缺腿超时样例」「出站孤儿样例」→ 行程贯验
```

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 刷卡点 | 带卡号/站点/方向/事件时的进出闸事件 |
| 开腿账 | 已进站尚未出站的在途开腿 |
| 行程账 | 进站+出站成对后的正式行程 |
| 旁路匣 | 缺腿超时 / 出站孤儿 / 重复进站等，行级「待回正/已回正」状态 |
| 回正审计 | 回正写闸留痕，与旁路编号一一对应 |
| 行程贯验 | 成对刷卡 ↔ 行程笔数 ↔ 旁路命运互证 |

## 旁路回正架构（全局唯一口径）

两架构择一，全系统只贯彻**口径乙：显式回正写闸**（口径甲「终态不可回正、整票拒绝」不采用）。

- 旁路行是终态「待回正」：装载路径与任何无入口调用都**禁止改其刷卡点命运**；
- 只有 `POST /api/replay/{bid}` 回正写闸可改命运，且**旁路关闭、刷卡命运、开腿/行程写入、审计同票事务同成败**；
- 回正审计对旁路编号 UNIQUE：重复回正幂等返回原审计，**绝不双行程**；
- 写闸 `BEGIN IMMEDIATE` 与装载串行化（`busy_timeout` 等待），并发下**不得半截开腿**；
- 只读接口 `GET /api/replay/preview/{bid}` 返回 `{旁路编号, valid, 是否允许回正, 原因, 重放结果, 审计编号}`，先看后写。

两口径可区分点：对出站孤儿旁路调回正——甲永远拒绝且零行程；乙在同卡存在在途开腿时成对成功、旁路关闭并新增一笔行程（带审计编号），无在途开腿时拒绝且零新增。

可回正原因：出站孤儿（重放成对）、缺腿超时 / 重复进站（重新开腿）；未知站点、方向非法为终态缺陷，写闸 422 拒绝。
